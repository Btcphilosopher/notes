### 10. How sensitive are results to TIM resistance?
With the active-air heatsink (baseline TIM k=3 W/mK, 50 um, 5 mm^2K/W per interface: Tj 34.05 degC): bulk k 1 -> 8 W/mK moves Tj 36.7 -> 33.0 degC; contact resistance 1 -> 50 mm^2K/W per interface moves it 33.3 -> 40.3 degC; bond-line 25 -> 100 um moves it 33.3 -> 35.5 degC. The three sweeps collapse onto one line: **0.073 K of junction temperature per mm^2K/W of total TIM1 resistance** (t/k + 2 R''), i.e. the TIM acts as a series resistance in the lid path. Contact resistance is the dominant TIM uncertainty and must be measured; bulk conductivity matters least once it exceeds a few W/mK.

### 13. Has a HotSpot or 3D-ICE comparison actually been completed?
**HotSpot 7.0 - yes, the real binary was built from the v7.0 tag and run** (grid model; steady 64x64, transient 32x32). **Result: no agreement.** ThermalLab is hotter in every block by 0.69-1.00 K (11-12 % of the rise); hottest block agrees (A). Both tools are mesh-converged (ThermalLab moves <= 0.04 K across mesh levels), so this is model structure. A third, independent axisymmetric finite-volume solver on a uniform-power block gives a chip-mean rise of 8.05 K vs ThermalLab 8.01 K (-0.55 %) and HotSpot 7.18 K (-10.8 %): the evidence supports ThermalLab and points at HotSpot's lumped periphery model. Transient (0.6 s horizon - HotSpot's grid transient costs ~48 s per simulated second): max difference 0.66 K with physical heat capacity, 1.16 K with HotSpot's C_FACTOR=0.333 applied. Non-equivalences are listed in `reports/compare/comparison.json`. This is a statement about the tools, not a verdict that HotSpot is wrong for its purpose.

**3D-ICE 4.0 - yes, the real binary was built from the 4.0 tag and run.** Single die: block-average steady temperatures within 18.6 mK (0.35 % of the rise), peaks within 6.2 mK; two-die stack: 4.0 mK average, 12.3 mK peak. Transient with the same implicit step (dt 0.01 s): 21.7 mK (single) and 6.8 mK (stack); against a second-order ThermalLab step the difference is 165 mK, which is 3D-ICE's own first-order time error (3D-ICE's scheme is inferred from this agreement, not read from its documentation). 3D-ICE has no package overhang, so package spreading is not part of this comparison; microchannels and plugin heat sinks were not exercised. 3D-ICE is GPL-3.0: it is called as an external binary and not redistributed.

## 5. Open engineering issues

- HotSpot 7.0 disagrees with ThermalLab by ~11 % of the temperature rise on its own default package stack; the independent axisymmetric solver sides with ThermalLab, but HotSpot's peripheral-node model has not been dissected line by line.
- No real SilicaFlux geometry, power, package or timing data: every temperature is a simulation of placeholders. Replace via CSV/JSON/DEF (floorplan), instance power CSV, PowerGrid export schema, Liberty-corner timing CSV.
- The real PowerGrid, FloorplanLab, TimingFlow and TwinLab interfaces were not accessible; adapters follow schemas defined in this project and need converters/verification against the real exports (an OpenROAD report_power parser is not implemented because no sample report was available).
- Direct sparse solves are memory-limited (~90k cells on 4 GB). The ILU-CG path exists but has not been validated at scale; a multigrid or domain-decomposition solver is needed for full-chip nanometre-resolved models.
- Junction temperature is the peak of an effective source layer of assumed thickness; no device-level self-heating (sub-micron hotspots) is resolved.
- Thin-film silicon, BEOL via-enhanced through-plane conductivity and passivation films are bulk/homogenised assumptions.
- Cooler models are lumped (R_sa, h, thermal mass); no CFD. The vapour-chamber effective conductivity is an assumption.
- Throttling studies assume an activity-scaling mechanism that SilicaFlux hardware may not have.
- Reliability output is screening only; no technology-qualified Arrhenius / Coffin-Manson parameters were supplied.
- Crank-Nicolson rings on abrupt power steps of the stiff die/TIM mode (several kelvin of difference at dt = 1 s against the finest-dt trace); use implicit Euler for step workloads or very small initial steps.
- Instance-level power (DEF + instance CSV) attaches through the Python API (`examples/def_demo/`); the YAML/CLI path consumes block power only.
- 3D-ICE comparison covers conduction stacks; microchannel cooling, non-uniform meshes and plugin heat sinks were not compared.
- The interactive dashboard was generated and structurally checked but not exercised in a browser in the build environment; the 3-D volume view needs WebGL (use --no-3d otherwise).
